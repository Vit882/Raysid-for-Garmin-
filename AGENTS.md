# AGENTS.md – how to work on the project

A guide for anyone taking over the project: an AI agent (Claude, Codex and others) or a human. Read all of it before you start changing code. Then, depending on the task, open the relevant document in `docs/`.

## What it is

`Raysid Garmin` is a Connect IQ **watch-app** written in **Monkey C** for the Garmin fēnix 7X Pro. It reads the Raysid dosimeter over Bluetooth LE and can:
- show values, a chart and overload (OVL);
- run alarms and clicks, vibration and flashlight according to cps;
- change settings stored in the Raysid;
- record GPS points with dose and upload them via the phone to the Žhavá místa website.

The users are Czech and Polish hunters of radioactive spots. The app is distributed as a `.prg` per watch model on GitHub and is being prepared for the Connect IQ Store as one `.iq` package for all models in `manifest.xml`.

## Hard rules

1. **No secrets in the repository.** The developer key (`*.der`, `*.pem`), Žhavá místa API keys and watch logs (they contain location) are never committed; `.gitignore` guards them. The API key is never written to the log or the display; the menu shows only the end of the key.
2. **Clean compile.** Every change must pass `monkeyc ... -l 3 -w` (strictest type checking, see [docs/BUILDING.md](docs/BUILDING.md)). Without that, the work is not done.
3. **Watchdog.** Connect IQ terminates the app when a single handler (onUpdate, timer, BLE callback) runs too long. Loops must be linear and bounded: the chart iterates only over the visible window, the parser has the `JUNK_MAX` cap, point merging processes `CMP_STEP` chunks per call and deletion `gcStep` 10 chunks. Nothing quadratic, no recursion over data.
4. **Buttons:**
   - Button holds are not used: a long DOWN opens the system alarms and a long UP opens the watch settings. LIGHT belongs to the watch.
   - Touch and swipe are ignored.
   - START opens the menu, DOWN switches screens, UP performs the current screen's action and BACK exits the app.
5. **Write to storage only via `put(key, value)`** (RaysidApp.mc). It does not crash when storage is full and returns `false`. Add any new key in `Application.Storage` to the table in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Loading must handle a missing value as well as a value of a different type: use `load()` or `instanceof` and clamp it to the valid range.
6. **Texts only in `Tr.mc`, always in all three languages** (`:key => ["cz", "en", "pl"]`):
   - Code calls `Tr.t(:key)`.
   - Keep menu labels short, about 20 characters at most; the round display is narrow.
   - Use only characters the watch fonts are sure to have: Latin letters with diacritics, `×` and `µ` are fine, arrows `→` and the ellipsis `…` are not (write `>` and `...`).
   - After changing the help, run `python3 tools/gen-guide.py`.
7. **Measurement safety:**
   - Alarms, clicks and mapping points use **instantaneous** values, never the display average.
   - During overload (OVL) no points are saved and an enabled dose or cps alarm always sounds.
   - Alarm limits stay below the Raysid overload (`ALARM_CPS_MAX`, `ALARM_DOSE_MAX`).
8. **Never delete unsent data** because of a temporary error. The Uploader discards only batches the server rejected because of their content (400/409/413/422). Other errors are retried.

## Conventions

- **Code comments** are in English (ASCII only), brief, and explain why. **User-visible texts** live in `Tr.mc` in all three languages (cz, en, pl), with diacritics.
- **Documentation** is in English. The user guide is generated in English, Czech and Polish by `tools/gen-guide.py`.
- **Names:** classes `PascalCase`, functions and variables `camelCase`, private fields `_name`, constants `UPPER_CASE`.
- **Colors** (MIP display, 64 colors):
  - dose orange `0xFFAA00`, cps blue `0x00AAFF`;
  - arc and text at UP yellow `0xFFFF00`;
  - alarm red;
  - stale values dark gray.
  Colors outside the MIP palette break up into dithering on the display.
- **Value format:** dose `0.12 / 1.23 / 12.3 / 123 uSv/h`, above 999.5 in mSv/h; cps `30.6`, above 1000 `1.23 / 12.3 kcps` (`doseNum`, `cpsNum` in RaysidDelegate.mc).
- **UI terminology:** in Czech "cvakání" (not pípání or klikání), "dělička", "Žhavá místa", "mapování"; in English "clicks", "divider", "Žhavá místa", "mapping".
- **Versions:** `APP_VERSION` is set in `build.sh` and changes only on the project maintainer's instruction. `BUILD_NUM` counts builds sent for testing and only `build.sh` increments it. For a plain compile check, call `monkeyc` directly.

## Workflow for a change

1. Read the affected modules in full and the relevant chapter in `docs/`. The code is tightly coupled through `RaysidState`.
2. Keep the change as small as possible and in the style of the surrounding code.
3. Go through the impacts:
   - menu (labels and their refresh after returning, `refreshItem`);
   - saving and loading settings;
   - all three languages and the help;
   - screens in every state: no connection, no data, OVL, alarm, debug screen, mapping off, on, paused or full.
4. Compile with `-l 3`.
5. Update the documentation (`docs/*.md`, the user guide via `tools/gen-guide.py`, the menu map via `tools/gen-menu.py` (update its structure when the menu changes)) and `CHANGELOG.md`.
6. Test build: `bash build.sh`. The result is in `build/Raysid.prg`.

## Testing

- **The simulator** needs the official device definition (Garmin SDK Manager, sign-in). With a simplified definition you can only compile.
- **Logic without the watch:** verify more complex logic (parser, point merging, upload queue) with a small Python model, as in the reviews in `docs/`.
- **On the watch:**
  - Turn on Display > Debug screen. Measurements and events are then written via `System.println` to `GARMIN/APPS/LOGS/<.prg name>.TXT`. The file must already exist on the watch; the watch may list the app under a name such as "Raysid (1)".
  - Crashes are in `GARMIN/APPS/LOGS/CIQ_LOG.YML`.
- **Checklist after a change:**
  - Raysid connect and disconnect;
  - values and chart;
  - alarm (sound, vibration, flashlight, silencing);
  - OVL;
  - Raysid menu with and without a connection;
  - mapping: start, pause, resume, app exit;
  - upload with and without the phone.

## Watch and Raysid limitations that have already cost time

- **Raysid:**
  - Without a ping every 4 s it disconnects after 10 s.
  - It has a Bluetooth connection with only one device (close the phone app).
  - It sends data about every 240 ms; older documentation says 2 s.
  - After a restart it may change the packet delimiter (0x84 → 0x10).
  - Settings are read with the same sequence the official app uses (ping with screen 9 before 0x1b 01); without it the Raysid does not respond.
  - See [docs/RAYSID-PROTOCOL.md](docs/RAYSID-PROTOCOL.md).
- **Watch:**
  - Connect IQ allows only one pending BLE request, so BleManager has a queue.
  - The vibration motor can distinguish at most about 4 pulses per second.
  - The click timer runs at 100 ms, so more than 10 signals per second is not possible.
  - The launcher icon is 40×40 px on most MIP models; other sizes are in `resources-icon<N>` (see `monkey.jungle`).
  - Connect IQ 3.x (fēnix 6) allows at most 9 arguments per method; pass more values as an array.
  - Build all models at once with `monkeyc -e` (the Store package) to catch API differences.
  - RSSI is available only while scanning.
  - An app installed over USB (sideload) does not receive settings from Garmin Connect, so the API key is entered on the watch.
- **Upload:**
  - It works only via the phone (`Communications.makeWebRequest`): HTTPS and JSON only, no multipart.
  - The website therefore has its own endpoint, see [docs/zhavamista/endpoint-proposal.md](docs/zhavamista/endpoint-proposal.md).

## Releases (GitHub Releases)

- **When:** a release with ready-made `.prg` files is made **only on the project maintainer's instruction**.
- **How:** put the `.prg` files and `notes.md` (release description, English) into `releases/v<version>/` and push to `main`. The workflow `.github/workflows/release.yml` creates the tag and the release with the files; an existing release is not changed. A test build in `releases/` is published, so only commit there what the maintainer approved.
- **One `.prg` per watch model.** The file name contains the version, build and Connect IQ device id, for example `Raysid-1.1-b82-fenix7xpro.prg`. The release description gives the full model name for each file.
- **Other models:** when a build for another model is made at a user's request (entry in `manifest.xml` and layout verification), it is added to the release and from then on included in **every subsequent** release.
- **The list of supported models** and their verification status is in the README, section Supported watches.
