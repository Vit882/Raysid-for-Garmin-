# Proposal for an endpoint for uploading routes from Garmin watches

For the Žhavá místa API maintainer. The Raysid app for Garmin watches (Connect IQ) records route points (GPS, dose rate from the Raysid dosimeter, cps) and should upload them to the website by itself through the phone.

## Why the current API is not enough

Today, routes can only be created by uploading a file via `POST /api/1.0/all/managedata?tab=upload` (multipart/form-data). Garmin watches send data exclusively with the `Communications.makeWebRequest` function, which can send the body only as JSON or `application/x-www-form-urlencoded`. Connect IQ does not support multipart or file upload. In addition, the watch has little memory, so it cannot send a route all at once and sends it in batches.

`POST /api/1.0/{device}/value` is for stationary stations and does not accept a position, so a route cannot be assembled from it.

## Proposed endpoint

```
POST /api/1.0/all/route-points
Content-Type: application/json
Authorization: Bearer <token>      (or X-API-Key: <key>, whichever the maintainer chooses)
```

Request body:

```json
{
  "client_route_id": "garmin-3a9f1c-1791916357-1",
  "batch": 0,
  "final": false,
  "name": "Garmin 13. 10. 2026 18:40",
  "device": "RAYSID",
  "points": [
    [50.0875000, 14.4213000, 1791916357, 0.088, 12.3],
    [50.0875062, 14.4213095, 1791916359, 0.085, 11.8]
  ]
}
```

- `client_route_id`: route identifier generated by the watch (device, start time and part number). The first request with a new `client_route_id` creates the route, further ones add points to it.
- `batch`: sequence number of the batch within the route, from 0. When the watch gets no response, it sends the same batch again. The server should recognize it by the pair `client_route_id` + `batch` and not store it a second time (reply with a normal `ok`).
- `final`: `true` on the last batch of the route. The server can then finalize the route (recompute tiles, approval and the like). A route has at most 5000 points, then the watch starts a new one with another `client_route_id`.
- `points`: array of points `[lat, lng, time, µSv/h, cps]`. Time is unix time in seconds (UTC). A batch typically has 50 points.
- `name` and `device` can be taken from the first batch only.

Response:

```json
{ "state": "ok", "route_id": 5790, "points": 150 }
```

On error, HTTP 4xx and `{"state": "error", "message": "..."}`. On 401 the watch shows that the key is wrong and stops sending. On 5xx it tries again later.

## Authentication

Ideally a long-term user key (like `X-API-Key` for stations), entered once in the app settings in Garmin Connect. The Bearer token from `/login` is valid for only 30 days and would have to be replaced regularly.
