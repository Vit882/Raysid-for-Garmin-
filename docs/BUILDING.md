# Building and installation

How to compile, sign and sideload the Raysid Garmin app to the watch, and how to read logs from it. Intended for a developer or AI agent taking over the project without further context. The protocol is described in `docs/RAYSID-PROTOCOL.md`, app usage in `docs/USER-GUIDE.md` (Czech: `docs/USER-GUIDE-CS.md`, Polish: `docs/USER-GUIDE-PL.md`; all three are generated by `tools/gen-guide.py` from `source/Tr.mc`).

## 1. Overview

| Item | Value |
|---|---|
| App type | Connect IQ `watch-app`, Monkey C language |
| Target watch | fēnix 7X Pro, tested on fēnix 7X Pro Sapphire Solar (id `fenix7xpro`), the only product in `manifest.xml` |
| Minimum API | 3.2.0 (`minApiLevel` in `manifest.xml`) |
| Permissions | `BluetoothLowEnergy`, `Positioning`, `Communications` |
| SDK used | Connect IQ SDK 9.2.0 |
| Jungle | `monkey.jungle` (only `project.manifest = manifest.xml`) |
| Output | `build/Raysid-<device>.prg`, for fenix7xpro also a copy `build/Raysid.prg` |

Repository structure:

| Path | Content |
|---|---|
| `source/*.mc` | source code |
| `source/BuildInfo.mc` | **generated by `build.sh`**, do not edit by hand |
| `resources/drawables/` | launcher icon `launcher_icon.png` (40×40) |
| `resources/strings/strings.xml` | app name and setting labels in Garmin Connect |
| `resources/settings/` | app settings in Garmin Connect (uploading to Žhavá místa) |
| `build.sh` | build with a build number |
| `build/` | build outputs and `build-number.txt` |

User interface texts (Czech, English, Polish) are not in `resources/strings` but in `source/Tr.mc`. The language is switched in the app, not via `<iq:languages>` in the manifest.

## 2. Requirements

### Java

The `monkeyc` compiler is a Java application. You need a JDK or JRE in `PATH` (`java -version`). The project's cloud environment has OpenJDK 21 and compiling works with it.

### Connect IQ SDK

The project is compiled with **Connect IQ SDK 9.2.0**.

- **Usual way:** install the **Connect IQ SDK Manager** from https://developer.garmin.com/connect-iq/sdk/, sign in with a Garmin account, download SDK 9.2.0 (or newer) and, in the **Devices** tab, the device "fēnix 7X Pro / Solar / Sapphire Solar" (`fenix7xpro`).
- **Project cloud environment:** `/mnt/project-files/.toolchain/` contains a prepared toolchain outside the repository (described in its `README.txt`):
  - `sdk/`: SDK 9.2.0, only `bin/`, `share/` and `resources/` (no documentation or samples),
  - `Devices/fenix7xpro/compiler.json`: a hand-written device definition (see below; the older `Devices/fenix7x` is only for the fēnix 7X without Pro),
  - `developer_key.der`: the developer key of this environment (see chapter 3).

The shared directory may be mounted as `noexec`, so `monkeyc` is run via `bash`: `bash /mnt/project-files/.toolchain/sdk/bin/monkeyc ...`.

Optionally VS Code with the **Monkey C** extension (Garmin). The command `Monkey C: Verify Installation` checks the SDK.

### Device definitions

The SDK looks for device definitions in `~/.Garmin/ConnectIQ/Devices/<id>/`.

**Official definitions** are downloaded by the SDK Manager, and the download **requires signing in with a Garmin account**. They contain everything: `compiler.json`, `simulator.json`, fonts, button layout, the watch image for the simulator.

**The substitute definition in the toolchain** (`/mnt/project-files/.toolchain/Devices/fenix7xpro/compiler.json`) was created because the official definition could not be downloaded without signing in. Installation:

```bash
mkdir -p ~/.Garmin/ConnectIQ/Devices
cp -r /mnt/project-files/.toolchain/Devices/fenix7xpro ~/.Garmin/ConnectIQ/Devices/
```

What the substitute definition can and cannot do:

- **The part number** (`partNumber`) in the substitute definition is not verified; it has no effect on sideloading.
- **It is enough for a compile check**, including strict type checking (`-l 3`), and for producing a `.prg`.
- It contains only basic data: round 280×280 display, 8 bits per pixel, family `round-280x280`, 40×40 icon, watch-app memory limit 786 432 B, Connect IQ 5.2.0, languages `ces`, `eng` and `pol`. The values are estimated, not taken from Garmin (`displayName` is "fenix 7X Pro (stub for compile check; part number not verified)").
- **You cannot run the simulator with it** (`simulator.json`, fonts and other files are missing; the cloud also lacks the simulator libraries).
- It is not certain that a `.prg` built against it will run on the watch the same way as a build against the official definition. So far it works on the watch, but on any odd behavior (crash at start, wrong fonts, memory error) first try building against the official definition.
- Do not upload to the Connect IQ Store with it (always build the `.iq` package against the official definitions).

## 3. Developer key

Connect IQ signs every build with a 4096-bit RSA private key in DER format.

**Every developer generates their own key** (or uses `Monkey C: Generate a Developer Key` in VS Code):

```bash
openssl genrsa -out developer_key.pem 4096
openssl pkcs8 -topk8 -inform PEM -outform DER -in developer_key.pem -out developer_key.der -nocrypt
```

Rules:

- **Never commit the key** and never paste it into documentation, issues or chat. It belongs outside the repository (e.g. next to the SDK). The repository's `.gitignore` guards against it (`*.der`, `*.pem`, `developer_key*`, `build/`).
- **Do not change the key for an installed app.** An update sideloaded over USB with the same app id (`manifest.xml`, attribute `id`) and **the same key** keeps the app's storage on the watch: settings, Raysid history, recorded and unsent points. A build signed with a different key behaves as a different app and you lose the data.
- In the project's cloud environment the key is at `/mnt/project-files/.toolchain/developer_key.der`. `build/Raysid.prg` is signed with it, and because this build is installed on the test watch, further test builds for it must be signed with **this** key.
- Do not change the app id in `manifest.xml`. The storage on the watch and the identity in the Connect IQ Store depend on it.

## 4. Building with `build.sh`

```bash
bash build.sh            # fenix7xpro
bash build.sh fenix7     # another device (must be in manifest.xml and have a definition)
```

What the script does (in this order):

1. Changes to the repository directory. It takes the toolchain from the `TOOLCHAIN` variable, default `/mnt/project-files/.toolchain`. It expects `sdk/bin/monkeyc` and `developer_key.der` there. On your own computer, set `TOOLCHAIN` to the directory containing `sdk/` (or a symlink to the SDK) and your key.
2. Computes the next build number from `build/build-number.txt` (if the file is missing, it starts at 1; it creates the `build/` directory itself).
3. Rewrites `source/BuildInfo.mc` with the constants `APP_VERSION`, `APP_YEAR`, `BUILD_DATE` (today's date) and `BUILD_NUM`. They are shown in the app under Help > About (function `aboutText()` in `RaysidDelegate.mc`).
4. Compiles `monkeyc -d <device> -f monkey.jungle -o build/Raysid-<device>.prg -y <key> -l 3 -w`.
5. After a successful compile, saves the new number to `build/build-number.txt` and, for fenix7xpro, copies the result to `build/Raysid.prg`.

**The app version** (`APP_VERSION`, currently `"1.1"`) and the year (`APP_YEAR`) are hard-coded in `build.sh`. For a new release change them there, not in `BuildInfo.mc`, because that file is overwritten on the next build.

The build number distinguishes test builds sent to the watch. It increases only with a successful `build.sh`; for a mere compile check call `monkeyc` directly (chapter 5).

## 5. Compile check only

When you only want to verify that the code compiles (after a change, during review), call `monkeyc` directly with output outside the repository. The build number does not increase and `BuildInfo.mc` does not change:

```bash
bash /mnt/project-files/.toolchain/sdk/bin/monkeyc \
  -d fenix7xpro -f /mnt/project-files/raysid-garmin/monkey.jungle \
  -o /tmp/raysid-check/check.prg \
  -y /mnt/project-files/.toolchain/developer_key.der \
  -l 3 -w
```

- `-l 3` is the strictest type checking (0 off, 1 gradual, 2 informative, 3 strict). The code currently passes it with no errors and no warnings, and it should stay that way.
- `-w` prints warnings.
- The result should be `BUILD SUCCESSFUL`.
- `monkeyc` also creates helper directories next to the output (`gen/`, `internal-mir/`, `external-mir/`) and files `*.debug.xml` and `*-settings.json`. So direct the output to a temporary directory, not into `source/`.
- `-y` is required even for a check. Any key will do.

## 6. Sideloading to the watch

1. Connect the watch with a USB cable. **Beware of charge-only cables**: the watch charges but the computer does not see it. If nothing appears, try another cable.
2. The watch uses **MTP**, not USB mass storage:
   - Windows: appears as a portable device.
   - macOS: OpenMTP or Android File Transfer.
   - Linux (KDE): Dolphin with `kio-extras` (protocol `mtp:/`).
   - Linux (command line): the `mtp-tools` package (`mtp-detect`, `mtp-files`, `mtp-sendfile`, `mtp-getfile`), or mounting via `jmtpfs` or `go-mtpfs`. Disconnecting and reconnecting the watch sometimes helps when another program grabs it (e.g. GNOME gvfs).
3. Copy `build/Raysid.prg` to `GARMIN/APPS/` on the watch.
4. Disconnect the watch. The "Raysid" app is in the apps list (START > Apps, or at the end of the activity list).
5. Before starting it, close the Raysid app on your phone. The Raysid keeps a BLE connection with only one device.

When updating, overwrite the existing file with the same name and sign the build with the same key (chapter 3).

## 7. Logs from the watch

Everything is in `GARMIN/APPS/LOGS/` on the watch.

### App debug log

The app writes `System.println()` only with the **debug screen** enabled (menu Display > Debug screen). The watch saves the output to `GARMIN/APPS/LOGS/<app file name>.TXT`, but **only if that file already exists**. The watch does not create it; you have to create it empty over MTP.

The file name matches the name under which the watch registers the app. That may not be `Raysid`: the watch may register the sideloaded app as e.g. `Raysid (1)`, and the log is then `Raysid (1).TXT`. Check what the file is called in `GARMIN/APPS/`, and if unsure, create both (`Raysid.TXT` and `Raysid (1).TXT`). When the log grows, the watch may move it to a `.BAK` next to it.

Line formats (separator `;`, the first column is `System.getTimer()` in ms):

| Line | Written by | Meaning |
|---|---|---|
| `time;cps;dose;XY` | `BleManager.onCharacteristicChanged()`, at most every 2 s | cps, dose rate in µSv/h, `X` = cps OVL, `Y` = dose rate OVL (0/1) |
| `time;P;HEX` | `RaysidParser.logPacket()` | the whole packet in hex: `0x22`, `0x18`, `0x23` always, `0x17` when the overload flag changes, others when the content changes; `0x21`, `0x02` and `0x06` are not logged |

Logs may contain the Raysid name and measurement times. Do not put them in the repository.

### Crashes

An app crash is written to `GARMIN/APPS/LOGS/CIQ_LOG.YML` (`CIQ_LOG.TXT` on some firmware). It contains the error type and a call stack with line numbers. To look them up, use `build/Raysid-<device>.prg.debug.xml` from the **same** build.

## 8. Supporting another watch model

The app is written and tested only for the fēnix 7X Pro Sapphire Solar. For another model:

1. **Manifest:** add `<iq:product id="..."/>` to `<iq:products>` in `manifest.xml`. You can find the id in the SDK Manager or in the directory name in `~/.Garmin/ConnectIQ/Devices/`.
2. **Device definition:** download the official definition through the SDK Manager (Garmin account). Make a hand-written substitute like the fenix7xpro one only for compile checks.
3. **Compiling:** `bash build.sh <id>` produces `build/Raysid-<id>.prg` (`build/Raysid.prg` is copied only for fenix7xpro).
4. **BLE:** the device must support `Toybox.BluetoothLowEnergy` and Connect IQ 3.2.0 or later.
5. **Button marks:** `RaysidView.drawMenuHint()` draws arcs on the display edge next to the fēnix buttons; the angles are hard-coded (degrees from 3 o'clock, counterclockwise): START 24–36°, UP 174–186°, DOWN 204–216°. This fits five-button fēnix, epix, Forerunner 9xx and similar watches. For watches with a different button layout or touch only, the angles need adjusting (for example based on `System.getDeviceSettings()` or via a per-device resource), or the marks can be turned off.
6. **Controls:** the app relies on the START, UP, DOWN and BACK buttons. Touch, swipe and hold do nothing. Buttonless touch watches would need changes to `RaysidDelegate`.
7. **Icon:** the launcher icon size differs by model (`launcherIcon` in the device definition's `compiler.json`). For fenix7xpro it is 40×40 px. For other models, add an icon of the correct size to a resources directory with a device qualifier (e.g. `resources-fenix7/drawables/` with the same `drawables.xml`). The SDK uses `resources-<id>` directories for the given device automatically. Otherwise the compiler rescales the icon with lower quality.
8. **Display:** the layout is computed as a fraction of width and height (`h * 0.22` and similar) and assumes a **round** display. The display shape (`screenShape`) is not checked anywhere. On rectangular displays (Venu Sq, Edge) and other aspect ratios the layout needs checking. Texts are shortened so they do not overflow the round edge.
9. **Colors:** the icon and UI are tuned for a MIP display with a limited palette. On AMOLED (epix, Venu) consider smaller areas of bright color and the behavior of the backlight always on setting.
10. **Memory:** the watch-app memory limit differs by model. The chart keeps up to 600 measurements in memory and route recording uses app storage (about 4000 points). On weaker watches verify this in the simulator (memory view) with the official device definition.

## 9. Release checklist

1. Increase `APP_VERSION` (and `APP_YEAR` if needed) in `build.sh`.
2. Run `bash build.sh` and check that compiling with `-l 3 -w` passed with no errors and no warnings.
3. Check that `build.sh` generated `source/BuildInfo.mc` with the correct version, date and build number, and that it shows under Help > About.
4. Check constants that can be switched for testing, e.g. `OVL_CPS_ON` in `RaysidDelegate.mc` (currently `false`, "disabled for testing").
5. On a real watch with a Raysid, verify:
   - scanning and connecting, including choosing among several Raysids,
   - that the Raysid does not disconnect after more than 10 s (ping),
   - µSv/h and cps values against the Raysid display,
   - the Raysid menu: reading settings and changing the divider, clicking and alarms,
   - alarms, signals and OVL,
   - recording points and uploading to Žhavá místa,
   - updating over an existing installation (same key): settings and records are kept.
6. Go through the logs and `CIQ_LOG.YML` to check the app did not crash.
7. **No secrets:** the repository contains no `developer_key.*`, no Žhavá místa API key and no raw logs (btsnoop, watch logs). The default `zmKey` in `resources/settings/properties.xml` must stay empty.
8. Update `README.md` and the documents in `docs/` if behavior or the protocol changed.
9. For the Connect IQ Store: build the `.iq` package (`monkeyc -e -r ...` or `Monkey C: Export Project` in VS Code) against the **official** definitions of all products in the manifest, with your own key that you will also use for all future versions.
